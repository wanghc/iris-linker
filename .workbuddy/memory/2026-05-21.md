# 2026-05-21

## iris-linker VSCode 扩展开发

### 本地文件导出支持 (v0.0.6)
- 扩展导出功能从仅 `isfs://` 协议扩展为同时支持 `file://` 协议
- `package.json` 菜单 `when` 条件改为 `(resourceScheme == isfs || resourceScheme == file)`
- 新增 `.int` 文件类型支持
- 新增两个配置项：`iris-linker.localExport.defaultServer`（本地导出默认服务器）和 `iris-linker.localExport.stripPrefix`（路径前缀去除）
- `extension.ts`：拆分 `getSuggestedFileName()` / `getDocumentName()` 函数，`file://` 通过 workspace 相对路径计算文档名
- `tool.ts`：抽取 `buildServerConfig()` / `getAllServers()`；新增 `getLocalServerConfig()`；`exportToXMLContent()` 签名改为接收文档名字符串

### 修复断点不生效（两次迭代）
**第一轮**：`launch.json` 中 `outFiles` 指向 `out/` 但实际输出在 `dist/`；`sourcesContent: false` 导致 sourcemap 不含源码
**第二轮（最终修复）**：`preLaunchTask: "npm: compile"` 引用了 tasks.json 中不存在的 task，导致根本不编译
- `tasks.json`：新增 `"compile"` shell task（`npm run compile`）
- `launch.json`：`preLaunchTask` → `"compile"`，简化掉不必要的 `resolveSourceMapLocations` / `sourceMapPathOverrides`，添加显式 `"sourceMaps": true`
- 验证：sourcemap 中 sourcesContent 已嵌入，sourceMappingURL 已注入，路径 `../src/extension.ts` 等正确

### 本地导出服务器配置优化
- `getLocalServerConfig()` 优先级1改为读取 `objectscript.conn`（VSCode 自动合并 `.code-workspace` 和 `.vscode/settings.json`），无需额外配置 `iris-linker.localExport.defaultServer`
- `objectscript.conn` 中的 `username`/`password` 也一并读取，作为凭据优先来源
- `buildServerConfig()` 新增 `overrides` 参数支持覆盖凭据
- 清理了历史遗留的 `out/` 目录
