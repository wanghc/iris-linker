## iris-linker 批量同步冲突覆盖失败修复

### 问题
- 无冲突文件同步成功，但有冲突的文件同步失败
- `ignoreConflict=1` URL 参数似乎无效
- 在 vscode-objectscript 中手动保存冲突文件时，需要点击 "Overwrite On Server" 才能成功

### 根因分析（通过阅读 vscode-objectscript 源码确认）

**关键发现：`mtime` 字段含义**
- `mtime > 0`：服务器对比时间戳，不一致则报冲突。此时若 `ignoreConflict=false`，还会发 `IF-NONE-MATCH` HTTP 头
- `mtime = 0`：不做时间戳检查（等价于忽略冲突）
- `mtime = -1`：语义是"未知"，但某些 IRIS 版本可能当作有效时间戳处理

vscode-objectscript 的 `importFileFromContent()` 函数使用 `mtime: 0` + `ignoreConflict: true`
vscode-objectscript 的 `importFile()` 函数在 `overwriteServerChanges=true` 或 `mtime < 0` 时设 `ignoreConflict=true`

**我们的 bug**：`payload.mtime = -1`，某些 IRIS 版本把 `-1` 当作有效时间戳，导致冲突检测生效

### 修复
- `payload.mtime` 从 `-1` 改为 `0`（与 vscode-objectscript "Overwrite On Server" 行为一致）
- 日志中同步更新 mtime 值输出
