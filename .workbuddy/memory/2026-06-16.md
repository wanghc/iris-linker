## iris-linker 同步功能 Bug 修复

### 问题：同步提示成功但服务器上文件未更新

**根因分析**：两个 bug

1. **成功判断逻辑不完整**（核心问题）
   - Atelier API 响应格式是双层 status：
     - 外层 `status.errors`（传输层，通常为 `[]`）
     - 内层 `result.status`（文档层，可能含 `"ERROR #16002: ..."`）
   - 原代码只检查了外层 `status.errors.length === 0`，导致即使 `result.status` 含错误也报"成功"
   - 修复：同时检查 `!innerStatus.startsWith('ERROR')`

2. **CSP 文件 docName URL 编码缺失**
   - CSP 类文件 docName 以 `/` 开头（如 `/imedical/web/csp/xxx.csp`）
   - 直接拼入 URL 后变成 `/doc//imedical/...`（双斜杠），导致路由错误
   - 修复：使用 `encodeURIComponent(docName)` 编码

3. **新增 Output Channel 日志**
   - 创建 `vscode.OutputChannel('IRIS Linker')`
   - 同步过程中输出：Git 文件列表、请求 URL、payload 摘要、完整响应、成功/失败结果
   - 同步开始时自动 `outputChannel.show(true)` 显示 Output 面板
   - `importDocumentToServer` 新增第 5 个参数 `outputChannel?`

### 第二轮 Bug：同步到错误服务器 + CSP/JS 失败

**问题1：同步到了 138 而非 159**
- `getLocalServerConfig()` 返回值不含 `serverName`，无法在日志中确认实际选中的服务器
- 修复：`getLocalServerConfig()` 返回值新增 `serverName` 字段，并输出详细日志：
  - `objectscript.conn.server` 值
  - 实际 selected server name
  - `server.webServer` 完整内容
  - 解析后的 `baseURL`
- **排查方向**：检查 `intersystems.servers` 中 159 对应的 `webServer.host` 是否实际指向 138 的 IP

**问题2：CSP/JS 同步失败（CLS 成功）**
- 原因：批量同步用 `getDocumentName(fileUri)` 计算文档名，内部依赖 `vscode.workspace.getWorkspaceFolder(uri)`
- 当 gitRoot 与 VSCode 打开的工作区文件夹不一致时（如 git 在 `src/` 父目录，但 VSCode 只打开了 `src/`），`getWorkspaceFolder` 返回 `undefined` 导致报错
- 修复：新增 `getDocumentNameFromGitPath(gitRelativePath)` 函数，直接从 Git 相对路径 + stripPrefix 计算 docName，不依赖 `getWorkspaceFolder`
- 批量同步改为调用 `getDocumentNameFromGitPath(file)` 而非 `getDocumentName(fileUri)`

### 第三轮 Bug：getLocalServerConfig 读取 objectscript.conn.server 失败导致选错服务器

**问题**：
- settings.json 明确配置了 `"objectscript.conn.server": "159"`
- 但日志输出 `[CONFIG] objectscript.conn.server = "(未配置)"`，最终 fallback 到了 138

**根因分析**（通过阅读 vscode-objectscript 源码确认）：
- 原代码：`vscode.workspace.getConfiguration('objectscript').get('conn')` — **不带 scope 参数**
- vscode-objectscript 的做法：`config("conn", configName)` — **带 workspaceFolder scope**
- VSCode 不带 scope 的 `getConfiguration()` 合并 User/Workspace/Folder 多层级配置时，可能导致 `.server` 字段丢失或被覆盖

**修复方案**（`src/tool/tool.ts` 中 `getLocalServerConfig()` 函数重写）：
1. 新增第二个参数 `targetFolder?: vscode.Uri`
2. **方式A**：用 `vscode.workspace.getConfiguration('objectscript', queryScope).get('conn')` 带 folder scope 查询
3. **方式B**：作为对比/ fallback，输出无 scope 的查询结果到诊断日志
4. **多 folder 遍历**：当有多个 workspace folder 时，逐个扫描找有 `server` 配置的 folder
5. **增强 fallback**：检测 `intersystems.servers` 中是否有 `active: true` 的服务器，提示用户选择
6. 所有路径都输出 `[CONFIG-DIAG]` 详细诊断日志，方便后续排查
7. 同步调用处传入 `wsFolder.uri`，导出命令传入文件 `uri`

**改动文件**：
- `src/tool/tool.ts`: 重写 `getLocalServerConfig()`，新增 `pickServerManually()`
- `src/extension.ts`: 两处调用点传入 folder scope 参数
